# Macheim 1.3.3 — Rosetta check and Steam overlay in modded games

## Changes

- **Play Modded** checks for Rosetta on Apple Silicon before it opens Terminal. Modded play runs Valheim's x86_64 slice with `arch -x86_64`, and without Rosetta the Terminal window only printed `arch: posix_spawnp: env: Bad CPU type in executable` (#29, reported on macOS 27). Macheim now shows an error that names `softwareupdate --install-rosetta --agree-to-license`. Intel Macs skip the check.
- **Steam overlay** (Shift+Tab) in modded games (#30). When Steam starts Valheim it inserts `steamloader.dylib` and `gameoverlayrenderer.dylib` through `DYLD_INSERT_LIBRARIES` and sets `SteamOverlayGameId`, `SteamEnv` and `SteamClientLaunch`. Play Modded starts the game itself and only inserted the BepInEx doorstop. It now appends Steam's two libraries after doorstop when they exist in the default Steam install, and sets the same variables.

## QA — 2026-10-16

Machine: macOS 26.2, Apple Silicon, Rosetta installed, Valheim 1.0.17.

- Steam-launched vanilla Valheim: `ps -E` shows `DYLD_INSERT_LIBRARIES=<Steam>/steamloader.dylib:<Steam>/gameoverlayrenderer.dylib`, `SteamOverlayGameId=892970`, `SteamEnv=1`, `SteamClientLaunch=1`; `vmmap` shows `gameoverlayrenderer.dylib` mapped.
- Both Steam libraries are universal with an x86_64 slice, so they load in the Rosetta process.
- Script generated by 1.3.3 `build_launch_script`, run on an APFS clone with a clean BepInExPack 5.4.2351 and no `steam_appid.txt`: `Using steam APPID:892970`, `Steam initialized`, `Chainloader startup complete (0 loaded, 0 skipped, 0 failed)`, `gameoverlayrenderer.dylib` and `steamloader.dylib` mapped, game kept running.
- Rosetta probe (`arch -x86_64 /usr/bin/true`) passes on the test Mac. The missing-Rosetta path is covered by unit tests only; Rosetta was not uninstalled for testing.
- Rust: new tests `missing_rosetta_on_apple_silicon_explains_install_command`, `rosetta_check_is_skipped_on_intel`, `launch_script_injects_steam_overlay_after_doorstop` and `launch_script_without_steam_overlay_injects_only_doorstop` failed before the change; 47 offline tests pass (4 opt-in live tests not run). Frontend: 21 tests passed; TypeScript and production build passed.
- Bundled shader policy: 26 checks passed; plugin unchanged. Release version/provenance verification passed for 1.3.3.

## Limits

- The overlay was confirmed as loaded, not as drawn: the full-screen game window could not be captured from the automation session. Shift+Tab was not pressed in an automated test.
- If Steam is installed outside `~/Library/Application Support/Steam`, the overlay libraries are not found and modded games run without the overlay, as before.
- Macheim does not install Rosetta itself.
- Apple has said macOS 27 is the last release with full Rosetta support; later releases keep it only for older, unmaintained games. Modded play still depends on Rosetta, so a future macOS may need a different launch path.
- All 1.3.2 limits still apply.
