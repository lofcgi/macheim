# Macheim 1.3.2 — Steam app id launch fix and Change version

## Changes

- **Play Modded** passes `SteamAppId`/`SteamGameId=892970` to Valheim. The launcher runs the game binary directly rather than through Steam, so Valheim had to find its app id in `steam_appid.txt`. Steam ships that file in the macOS depot, but when it is missing Valheim logs `Failed to find APPID` / `Using steam APPID:0`, Steamworks never initializes, and the modded game closes right after BepInEx loads. Reported on r/valheim as Play Modded starting the game "vanilla".
- Installed Mods rows have a **Change version** action that opens the existing version picker for that mod's catalog (#22). Configs are kept, as in the Browse Mods picker from 1.2.0. Manual mods and BepInEx do not get the action.

## QA — 2026-10-11

Machine: macOS 26.2, Apple Silicon, Rosetta installed, Valheim 1.0.17 (Steam build 25730771).

| Case | `steam_appid.txt` | Result |
|---|---|---|
| 1.3.1 launcher, BepInExPack 5.4.2333 + installed mods | missing | `APPID:0`, `Steamworks is not initialized`, game exits ~70 s after launch |
| same, Steam already running | missing | same failure |
| env fix, 5.4.2333 + installed mods | missing | `Using steam APPID:892970`, `Steam initialized` |
| 1.3.1 launcher, clean BepInExPack 5.4.2351 | present | `Steam initialized`, `Chainloader startup complete (0 loaded, 0 skipped, 0 failed)` |
| 1.3.1 launcher, clean 5.4.2351, Steam closed before launch | present | `Steam initialized`, BepInEx loaded |
| script generated by 1.3.2 `build_launch_script`, clean 5.4.2351 | missing | `Using steam APPID:892970`, `Steam initialized`, BepInEx 5.4.23.5 loaded, game kept running |

- Clean-install cases ran on an APFS clone of the game folder. The user game folder and its `steam_appid.txt` were restored and left unchanged.
- Static checks: `libdoorstop_x64.dylib` is x86_64 and unchanged between BepInExPack 5.4.2333 and 5.4.2351; Valheim is a universal binary with hardened runtime plus `allow-dyld-environment-variables` and `disable-library-validation`, so DYLD injection is allowed.
- Rust: new regression test `launch_script_passes_steam_app_id` failed before the fix; 43 offline tests pass (4 opt-in live tests not run). Frontend: 21 tests passed; TypeScript and production build passed.
- Bundled shader policy: 26 checks passed; plugin unchanged. Release version/provenance verification passed for 1.3.2.

## Limits

- The reporter's exact "vanilla" symptom was not reproduced. On the test Mac the failing launch closed the game instead of relaunching it through Steam. If only BepInEx is installed, a modded launch looks the same as vanilla; `BepInEx/LogOutput.log` shows the loaded mod count.
- Valheim 1.0.17 breaks some ServerSync-based mods with `Field not found: ZRoutedRpc.Everybody`. That needs mod updates, not a Macheim change.
- Version pinning is not implemented. Update all still moves a downgraded mod to the latest version.
- All 1.3.1 limits still apply: no new shader coverage, Apple notarization or native ARM modded-game support.
